# Friends & Groups

Entry: Account sidebar or Profile → Friends & Groups. Routes use `#friends/chats`, `contacts`, `groups`, `add`, `requests`, `search-groups`, `select`, `name`, `qr`, `scan`, `notices`, and `thread/<id>` so browser Back/Forward works with the existing account navigation. Add Friend is also its own sidebar/Profile section (`FriendsView base="add-friend"`): `#add-friend`, `#add-friend/qr` and `#add-friend/scan` show search, your copyable User ID, My QR Code, Scan to add and Invite Friends; any other screen it opens goes to `#friends/...`.

The account page passes `createSupabaseFriendsRepository` (`src/lib/api/friends.ts`), so friends, requests and groups come from Supabase (`supabase/migrations/001_friends_groups.sql`). It reuses the existing `public.users` table (adds `auth_user_id`, `nickname`, `avatar_url`, `public_id`) behind a `profiles` view; no second profile table is created. RLS enforces every rule; accepting a request and creating a group run as RPCs (`accept_friend_request`, `create_group`) in one transaction. The view subscribes to Realtime so the New Friends badge updates live, and Search User ID does an exact server-side `public_id` lookup excluding your own ID. Direct and group messages are backed by Supabase (`public.messages`, `supabase/migrations/002_messages.sql`): RLS limits reads to a direct chat's two participants or a group's current members, and sends to yourself as a current friend or a group you belong to. New messages arrive over Realtime and reload the thread.

Chats are ephemeral. RLS hides a message 24 hours after `created_at` (which clients can't set), pg_cron deletes expired rows every 10 minutes, and each send also purges them in case pg_cron is unavailable. The view drops expired messages on screen every minute. Chat text can't be selected, copied, dragged or long-pressed, and in the Android app `ScreenSecurityPlugin` sets `FLAG_SECURE` while a chat is open, which blocks screenshots, screen recording and the recent-apps preview. Browsers can't block screenshots, so on the web this is limited to blocking copy.

`model.ts` holds models, validation, transitions, fixtures and the `FriendsRepository` interface. `createMockFriendsRepository` (localStorage, sample labels shown) is the default when no repository factory is passed and is used by tests. `FriendsIntegrations` reserves optional leaderboard/consented portfolio-sharing hooks; neither is implemented or enabled.

`components.tsx` provides reusable avatar, row, search, empty state, icons, QR and scanner. Camera access is requested only when the user opens Scan. The scanner follows the camera permission: turning it off stops the camera and shows how to re-allow it, allowing it again (or returning to the app) restarts scanning, and scanning your own QR is rejected. Denial, missing camera, invalid IDs, retry and camera shutdown on navigation/background are handled. Android CAMERA permission is already in the manifest. Verify permission prompts on a physical device when building the mobile app.

System sharing uses `NEXT_PUBLIC_APP_INVITE_URL` or the existing public app domain's `/signup/` page; clipboard fallback is used when Web Share is unavailable. All shared content stays generic and contains no dummy referral ID.

Run model checks from the repository root: `node --test frontend/test/friends.test.mjs`.
